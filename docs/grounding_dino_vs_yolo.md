# GroundingDINO vs YOLO：差異與分工

## 核心差異：開放集 vs 封閉集

| | GroundingDINO | YOLO |
|---|---|---|
| **偵測類型** | 開放集（Open-vocabulary） | 封閉集（Closed-set） |
| **類別定義方式** | 推論時用文字描述 | 訓練時固定 |
| **新增類別** | 改文字提示，無需重訓 | 必須重新收集資料並重訓 |
| **零樣本能力** | 強（未見過的類別也能偵測） | 無（未訓練的類別 = 看不到） |
| **推論速度** | 慢（Swin Transformer + BERT） | 快（10~100x 快於 GroundingDINO） |
| **模型大小** | 大（~172MB ~ 800MB+） | 小（YOLOv8n ~6MB，YOLOv8x ~130MB） |
| **邊緣設備部署** | 困難 | 容易（Jetson、工控機、手機） |
| **固定類別精度** | 中等（通用預訓練） | 高（針對目標類別 fine-tune 後） |
| **需要標注資料** | 不需要（零樣本可直接使用） | 需要（冷啟動問題） |

---

## 最關鍵的差距：冷啟動與新工站問題

### YOLO 的困境
```
想訓練 YOLO？ → 需要標注資料
想要標注資料？ → 需要先有模型 或 人工標注

→ 每個新工站、每個新類別都要從零開始人工標注
```

### GroundingDINO 如何解決
```
零標注 → GroundingDINO 生成第一批標注 → 人工校正 → 訓練 YOLO
                                                        ↓
                                              YOLO 加速後續標注
```

GroundingDINO 打破了「沒有資料就無法訓練」的惡性循環。

## 新工站場景的實際成本比較

| 場景 | YOLO 的做法 | GroundingDINO 的做法 |
|------|------------|---------------------|
| 新工站上線，有 3 個新零件類別 | 人工標注數百張 → 重新訓練 | 改文字提示：`"part_X . part_Y . part_Z"` |
| 工廠新增瑕疵類型（如「氣泡」） | 無法偵測，需重新收集與標注 | 直接用 `"bubble defect"` 開始偵測 |
| 跨工廠部署，類別略有不同 | 每個工廠訓練一個獨立模型 | 一個模型，每個工廠不同文字提示 |
| 驗證某個新類別是否值得收集資料 | 無法驗證（沒模型） | 直接用文字跑幾張圖評估可行性 |

## 「YOLO 也能輔助標注，為何還需要 GroundingDINO？」

這個問題的答案在於兩者扮演的**角色不同**：

> **YOLO fine-tune 後的輔助標注**：只能針對已訓練過的固定類別，對新類別無效。
>
> **GroundingDINO 的輔助標注**：不需要任何已有標注，任何能用文字描述的類別都能開始標注。

兩者並非競爭，而是接力：

1. **GroundingDINO** 負責冷啟動，用文字生成第一批標注
2. 人工校正這批標注
3. 用校正後的資料訓練 **YOLO**
4. **YOLO** 負責後續固定類別的快速輔助標注與生產環境部署

## 何時選用哪個工具

| 需求 | 建議工具 |
|------|---------|
| 全新工站，還沒有任何標注資料 | **GroundingDINO**（冷啟動） |
| 類別固定，需要快速大量標注 | **YOLO**（fine-tune 後） |
| 類別會不定期新增 | **GroundingDINO** |
| 部署到產線做即時偵測 | **YOLO** |
| 部署到邊緣設備（Jetson、工控機） | **YOLO** |
| 評估某個新類別的可行性 | **GroundingDINO**（零成本驗證） |
| 多工站共用一個偵測服務（類別各異） | **GroundingDINO** |
| 對已知固定類別追求最高精度 | **YOLO**（針對性 fine-tune） |

---

## 一句話總結

> **GroundingDINO 是「探索者」，YOLO 是「執行者」。**
> GroundingDINO 讓你在沒有任何標注的情況下啟動一個新工站的標注流程；YOLO 讓你把已知固定類別快速、輕量地部署到產線。兩者各有其不可替代的位置。
